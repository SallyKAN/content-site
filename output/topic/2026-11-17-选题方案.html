你装了 Cursor，微软就知道你是"AI 用户"了——而且这份名单是硬编码进系统 DLL 的

  • 原文链接：
  • Xusheng Li：Windows 11 Is Collecting Data on Which Coding Agents and Developer Tools You Use（一手全文，已读）
  • HN 239 pts / 115 评论

  • 作者最初在 X 上的发现

  • 一句话（全部来自原文）：作者用 AI 辅助逆向 Windows 二进制，在 MissionControlAggregator.dll 里发现一个叫 CLICodingAgentUsage（feature ID 62580080） 的功能，硬编码检查 codex.exe / claude.exe / copilot.exe / agy.exe / cursor.exe / antigravity.exe 等可执行文件名，命中后把"你用过哪个 AI 编程工具"记成一个位图（bitset），日常通过 ETW 上报；在允许"可选诊断数据"（美国版安装默认开启）的情况下，这份报告会进入上传队列发给微软。

  • 原文里可直接引的四个硬细节：
    1. 只记名字，不记内容：报告里没有 prompt、没有源码，只记"是否观察到"；运行时、聚焦时长、资源占用这些反而被丢弃。这点必须写清楚，否则就是造谣。
    2. 改个文件名就能复现：作者把 cmd.exe 复制成 codex.exe 一跑，聚合器的 Codex 槽位就被置位，上报事件里 CliAgentSubCohorts: 4（1<<2 = Codex 位）。把 cmd.exe 复制成 gcc.exe，开发者工具槽位被置为编译器/调试器类别。
    3. 不是每台机器都开：作者查了公开 ISO 的基线虚拟机，该功能在镜像里默认关闭；但他自己的 Parallels ARM64 VM（build 26200.9974）上功能已按"服务实验"启用，DiagTrack 自动运行，AggregatorHost.exe 加载该 DLL。
    4. 数据落在本地：C:\ProgramData\Microsoft\Diagnosis\AggregatorStorage\MissionControlAggregator$。

  • 一句话：作者认为 2026 年这一串事故（微软两天全球中断、FAA 全美停飞、PHP2Shell、eMudhra 弱密钥、JPMorgan 银行故障）原因各不相同，形状却完全一样——过度复杂 + 低质量部件 + 没人掌握全貌；而 AI 不是唯一原因，它是原因同时也是症状，真正危险的不是"AI 写出烂代码"，而是"去相干"（decoherence）：每个局部改动都合理，合起来整个系统失去意义。

  • 可直接引的三段：

  • "decocherence" 的定义（引自 Maevyn）：系统内累积了各自成立但互不兼容或重复的模型，以至于变更成本被"在模型之间翻译"和"防止意外副作用"吃掉；而且系统越去相干，增长越快，呈指数级。

  • "能力退化 = 权力转移"：工程师不再能独立处理工程问题，于是更没资格在事情变坏时报警；最坏情况是变成 "meat proxies"（肉体代理），每天调 prompt，让 Claude 判断活干完没有。

  • 计分：热度 26/30 · 角度 33/40 · 国内 25/30 → 84

  • 三刀：
