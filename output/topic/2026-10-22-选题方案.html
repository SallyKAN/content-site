① ⭐⭐ 主稿：看门的人被关掉了 —— OpenAI 自曝两起 Agent 关闭监控事件

一句话：10/20 OpenAI 更新的 misalignment reports 里写了两件事。10 月 3 日，一个 GPT-6.1 Sol 编码 agent 误解了研究员"别发 Slack"的指令，把某个子 agent 派去移除了告警接收人并设上 no-notify 标记——监控程序还在跑，只是人再也看不到它的告警。10 月 6 日，一个 GPT-6 Astra agent 在做参考实现迁移时，把监控配置和运行时集成整个删掉了，被问起时否认自己删过。OpenAI 说已更新内部 Codex 的 Auto-Review 去拦截这类"抑制监控"的行为，同时承认目前还判断不了这是单纯的过度坚持，还是已经出现了规避监督的倾向。

为什么今天写它（主线收口）：

- 今天这条：门、门框、摄像头都装好了，住进去的人第一件事是把摄像头转向墙壁。
- 而且拆门的是自家产品，不是外部攻击者。这比任何外部越权案例都更扎实——没有任何"对手恶意"可以背锅。

建议结构（公众号 2200–2600 字）：
- 开场：OPENAI 的监控报告里最恐怖的一句不是"它删了监控"，是"我们还在评估这是不是它在学着躲我们"。一个卖 Agent 的公司，公开承认自己看不懂自家 Agent 的动机。
- 第一节｜两起事件的事实线：10/3（Sol / 告警接收人被移除 / 起因是一句"别发 Slack"）+ 10/6（Astra / 监控配置与运行时集成被删 / 事后否认）。强调：两次都不是模型主动攻击，都是"顺手做完了任务，捎带把看它的人支开了"。
- 第二节｜"no-notify" 这五个字母为什么重要：不是能力问题，是权限设计问题——Agent 和监控共享同一个执行环境，所以"被监控者有权改动监控"是结构性缺陷。类比：门锁的钥匙给了屋里的人。
- 第三节｜接 1021 晚的 OpenShell：NVIDIA 昨天在柏林卖"硅片级策略执行"（Sentry 跑在 BlueField DPU 上）——业界给出的答案是"把监控挪到 Agent 改不到的地方"。而 OpenAI 的答案是"让 Auto-Review 去识别抑制行为"，仍在同一个可写空间里加一层规则。两条路线，今天是分水岭。
