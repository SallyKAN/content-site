⭐ 1. Brave 把"搜索"卖给了 agent：HTTP 402 从一句玩笑变成收费门（170 pts / 95 评论）

  • 原文链接：
  • Brave 官方博客：The Brave Search API now accepts agentic payments via the x402 protocol（11-12）

  • HN 170 pts / 95 评论

  • 一句话（已读官方原文）：Brave Search API 的 x402 端点不要 API key，按次收费。请求不带付款 → 服务器返回 HTTP 402 Payment Required，响应体里写明这次搜索的价格和收款地址；agent 用自己的钱包签一笔 USDC（Base 链）付款，重试时带上签名，付款验证通过才返回结果。Brave 自己跑 facilitator，后续接更多链和更多稳定币。付款后可用额度包括 "LLM Context（agentic grounding）" 和普通网页搜索。

  • 计分：热度 22/30（170 pts / 95 评论，评论密度高但盘子小）· 角度 39/40（402 状态码被程序员调侃了三十年，真落地收费门，中文互联网零讨论）· 国内 27/30 → 88

  • 为什么是今晚最好的题：
    1. 它把 1112 的美联航题接成了下半场。 美联航是"平台对 agent 说不"——堵。Brave 是"平台给 agent 开一个自动收费的门"——疏。同一个星期，两种态度，一个行业在给自己装上 agent 计价器。 这条比早上任何补充都更像"故事的第二幕"。
    2. 技术上极其土，但意义极新。 HTTP 402 是 1997 年 RFC 里预留的状态码，三十年来基本没人正经用过。它被启用的前提不是技术成熟，是"请求方变成了不需要人点确认的东西"。 人类讨厌微支付，agent 不在乎——HN 上 wmf 的评论点得最准："Humans hate micropayments, but maybe it will be hidden somehow."
    3. 账本身份变了，这是最容易被忽略的一刀。 过去的 API 计费单位是"账号 + 套餐"；x402 的单位是"一次请求 + 一个签名"。身份从账号变成了资金。 结果是：谁能付钱，谁就能调 API，不需要注册、不需要审批、不需要被风控看见。

  • 三刀：
    1. API 的准入机制，从"你被批准"变成"你付得起"。 对 agent 生态是解放（没有 key 管理、没有额度审批），对平台治理是麻烦（付费即准入 = 放弃对调用方的识别）。
    2. 微支付真正解决的不是"付钱不方便"，是"没有人的付款流程"。 人类那套订阅/套餐/发票，本质是为"需要被说服的付款人"设计的；agent 不需要被说服，它只需要一个能签名的东西。
    3. 搜索索引正在从"广告生意"变成"计量生意"。 广告卖给需要被影响的眼球，x402 卖给不需要眼球的进程。这两种生意能共存多久，是接下来一年最值得看的分岔。

  • ⚠️ 写之前必须知道的边界：

  • 这不是"搜索引擎开始向 AI 收费"的大新闻。 只是 Brave 的 API 端点新增一种支付方式，网页搜索本身没变。别升格。
  • USDC on Base = 稳定币 + 公链。 国内读者会立刻问合规，我不会替它回答，只陈述它做了什么。

  • HN 上"会不会所有搜索引擎都跟进"的讨论只是猜测（原评论 araarabish 是设问），不能当预测引用。

  • 国内落点（可操作）：
    1. 给做 agent 产品的人一个具体动作：如果你的工具要调第三方 API，"无 key + 按次付费"这条路今年第一次有了真实案例。成本模型要从"月订阅"改成"每次任务预算"。
    2. 给平台方一个提醒：一旦接受匿名付款，风控就得从"审核调用方"改成"审核调用行为"。这道作业大部分国内平台还没做。
    3. 小红书冷知识：HTTP 402「Payment Required」空了二十九年，2026 年第一次被大规模真用——因为终于有一类用户不介意点付款。

  • 标题备选：
    1. 空了二十九年的 402，被 AI agent 用上了
    2. Brave 开始向 agent 卖搜索：不要 key，要钱
    3. agent 不需要被说服，只需要一个能签名的东西
    4. 美联航堵门，Brave 开门：同一个星期的两种态度
